# 音声会話方式 比較結果

実施日: 2026-08-10  
対象: 現行3モデル直列構成と `gpt-realtime-2.1-mini`  
シナリオ: 日本語20件（ページ操作10件、説明・相談10件）

## 結果

| 指標 | 現行構成 | `gpt-realtime-2.1-mini` | 差 |
| --- | ---: | ---: | ---: |
| 初回音声 p50 | 4,313 ms | 1,241 ms | Realtimeが71%短縮、3.47倍高速 |
| 初回音声 p95 | 5,216 ms | 1,550 ms | Realtimeが70%短縮、3.36倍高速 |
| 初回音声 平均 | 4,363 ms | 1,263 ms | Realtimeが71%短縮 |
| 正規化CER（低いほど良い） | 10.3% | 34.5% | 現行が良好 |
| 完全一致認識率 | 65% | 40% | 現行が25ポイント良好 |
| tool call成功率 | 100% (20/20) | 90% (18/20) | 現行が10ポイント良好 |
| キャンセル処理 | 1.2 ms | 671.9 ms | 測定境界が異なるため直接比較不可 |

## 判定

会話の初動は `gpt-realtime-2.1-mini` が明確に優位であり、NFR-004の「発話終了から最初の応答音声までp95 2.5秒以内」を満たした。現行構成のp95は5.2秒で未達だった。

一方、今回の条件ではRealtimeの認識復唱精度とtool call精度が現行構成を下回った。したがって、音声経路を直ちに全面置換するのではなく、Realtimeを音声入出力・VAD・割り込みへ採用し、ページ操作toolの実行前にサーバー側で意図と引数を検証する構成を推奨する。複雑な比較・推薦は引き続き `gpt-5.4` へ委譲する。

## 失敗傾向

- Realtimeのtool call失敗は2件とも過剰呼出しだった。
  - S04「予算七百万円前後でおすすめはありますか」から `/models/` を呼び出した。
  - S17「荷室が広いモデルを比較したいです」から `/models/` を呼び出した。
- Realtimeの認識復唱では英字車名と固有語の揺れが目立った。
  - `SUV` が `SUE RU`、`LBX` が「エルビックス」になった。
  - S20では日本語入力を韓国語で復唱した。
- 現行認識でも `LM`、`LX`、静粛性、荷室などに誤認識があった。

## 測定方法

- 20件の原文を `gpt-4o-mini-tts` で24 kHz PCMへ変換し、両経路へ同一音声を入力した。
- 現行構成は `gpt-4o-mini-transcribe`、`gpt-5.4`、`gpt-4o-mini-tts` を直列実行した。
- Realtime構成は `gpt-realtime-2.1-mini` のserver VADと音声deltaを使用した。
- 初回音声は発話終了から最初の再生可能な音声データ受信までを測定した。
- CERは空白、句読点、全半角を正規化した文字列の編集距離で算出した。
- tool callは同じ関数定義と同じ操作ポリシーを両モデルへ与えた。期待時は関数名とpathの完全一致、非期待時は関数を呼ばないことを成功とした。

## 制約

- `gpt-realtime-2.1-mini` は統合モデル自身の入力transcriptを直接返さない。このため認識精度は、別セッションで「一字一句復唱」と指示した音声出力transcriptを代替指標としている。純粋なASR精度ではなく、音声理解・指示追従・復唱を合わせた精度である。
- tool call試験はモデル固有のtool判断を比較するためテキスト入力を使った。音声認識誤差との複合成功率ではない。
- 現行キャンセルはHTTP中断完了、Realtimeはサーバーの `response.cancel` 完了までを測った。ブラウザの再生バッファ停止を含まないため、数値を直接比較しない。
- Realtime WebSocketは測定中に断続的なHTTP 400と接続リセットが発生した。接続確立前のみ最大5回再試行し、初回音声時間には再試行時間を含めていない。実装時は接続成功率と再接続時間を別のSLOとして計測する必要がある。

生データは `voice-comparison.json`、再現用シナリオとスクリプトは `scripts/voice-scenarios.json` と `scripts/benchmark-voice.mjs` に保存した。
