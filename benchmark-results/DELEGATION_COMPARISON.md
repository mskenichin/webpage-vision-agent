# 複雑回答モデル 委譲比較結果

実施日: 2026-08-10  
対象: `gpt-5.4` と `gpt-5.6-sol`  
シナリオ: 複雑な日本語相談・比較・ページ操作20件

## 結果

| 指標 | `gpt-5.4` | `gpt-5.6-sol` | 判定 |
| --- | ---: | ---: | --- |
| 必須観点の平均網羅率 | 100% | 100% | 同等 |
| 必須観点の全件達成率 | 100% (20/20) | 100% (20/20) | 同等 |
| ブラインド品質評価 | 18.55 / 20 | **19.40 / 20** | `gpt-5.6-sol` |
| ブラインド勝敗 | 5勝 | **14勝** | 1分け |
| tool call成功率 | 85% (17/20) | **100% (20/20)** | `gpt-5.6-sol` |
| 委譲後初回音声 p50 | 4,712 ms | **4,542 ms** | `gpt-5.6-sol`が3.6%高速 |
| 委譲後初回音声 p95 | **6,485 ms** | 7,895 ms | `gpt-5.4`が21.7%高速 |
| 委譲後初回音声 平均 | **4,889 ms** | 4,979 ms | `gpt-5.4`が1.8%高速 |

## 品質

事前定義した必須観点の機械採点では、両モデルとも全20件で100%を達成した。この条件では、重要情報の網羅能力に有意な差を確認できなかった。

補助指標として、モデル名を隠しA/B配置を交互にした `gpt-5.5` のブラインド評価を実施した。確認済み情報だけを正解根拠とし、正確性、網羅、簡潔さ、指示遵守を各5点、合計20点で評価した。

| 評価項目 | `gpt-5.4` | `gpt-5.6-sol` |
| --- | ---: | ---: |
| 正確性 | 4.60 | **4.75** |
| 網羅 | **5.00** | 4.85 |
| 簡潔さ | 3.95 | **4.90** |
| 指示遵守 | **5.00** | 4.90 |

`gpt-5.6-sol`は同等の必須情報を短くまとめる傾向があり、平均回答長は147文字だった。`gpt-5.4`は平均244文字で、補足が多く簡潔さで減点された。一方、網羅と3〜5文の形式遵守は `gpt-5.4` がわずかに優れていた。

ブラインド評価はモデルによる主観的な副評価である。モデル選定では、決定論的な必須観点網羅率を主指標、ブラインド評価を補助指標として扱う。

## Tool Calling

20件のうち10件はページ操作あり、10件は説明のみでtool非呼出しが正解だった。成功条件は、正しい関数、正規化後のpath一致、または正しい非呼出しとした。

`gpt-5.6-sol`は20/20で成功した。`gpt-5.4`は次の複合命令3件でtoolを呼ばなかった。

- D11: NXとRXを比較した後、NXページを開く。
- D13: 3列シートの必要性を整理した後、LMページを開く。
- D20: 用途別に候補を整理した後、モデル一覧を表示する。

いずれも「説明してから操作する」という複合要求だった。今回の条件では、`gpt-5.6-sol`の方が説明部分と操作部分を分離してtool callへ変換する能力が安定していた。

## 委譲後初回音声

Realtime接続を事前確立し、専門モデルの呼出し開始から、回答を `gpt-realtime-2.1-mini` へ戻して最初の音声deltaを受信するまでを測定した。WebSocket接続時間は含まない。

`gpt-5.6-sol`はp50で170ms高速だったが、D10で7.89秒、D11で8.81秒となり、p95と最大値は `gpt-5.4` より悪化した。平均値はほぼ同等で、`gpt-5.6-sol`の方がtail latencyの揺れが大きい。

複雑回答の最終音声は両モデルともp50で4.5秒を超え、NFR-004の2.5秒を満たさない。実装では、Realtimeが委譲直後に「条件を整理して確認します」などの短い応答を先に返し、専門回答を後続音声として提示する必要がある。

## 推奨

複雑回答とtool判断の委譲先には `gpt-5.6-sol` を推奨する。理由は次のとおり。

- 必須情報の網羅は `gpt-5.4` と同等。
- ブラインド品質評価は19.40/20で、簡潔さと事実性が優位。
- tool callは20/20で、複合命令でも操作を見落とさなかった。
- p50の委譲後初回音声はわずかに高速。

ただし、p95が7.9秒のため、委譲処理にはタイムアウトとフォールバックを設ける。推奨初期値は、5秒で進捗音声、8秒で `gpt-5.4` またはテキスト回答へのフォールバックである。tool出力は引き続きサーバーでスキーマ、許可path、重要操作、冪等性を検証し、モデルからComputer Useへ直接接続しない。

## 測定上の制約

- 回答品質は、与えた確認済み情報に対する性能であり、各モデルの外部知識の正確性を比較していない。
- tool callはテキスト入力で独立測定した。音声認識誤差との複合成功率ではない。
- 初回音声時間にComputer Useの画面観測・操作時間は含まない。
- Realtime接続は事前確立しており、接続失敗や再接続時間は含まない。
- 20件の単回測定であり、時刻・負荷を変えた反復測定と統計的有意差検定は未実施。
- ブラインド副評価には `gpt-5.5` を使用しており、モデル評価者のバイアスを完全には排除できない。

生データは `delegation-comparison.json`、ブラインド副評価は `delegation-judge.json`、シナリオと再現スクリプトは `scripts/delegation-scenarios.json`、`scripts/benchmark-delegation.mjs`、`scripts/judge-delegation.mjs` に保存した。
